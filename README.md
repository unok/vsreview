# VSReview

VSReview は Git のコミットや GitHub の Pull Request の差分にレビューコメントを付け、AI Agent 向けの Markdown または JSON に出力する VS Code 拡張です。修正依頼に加え、コードを変更せず回答を求める質問も出力できます。

## 特徴

- 差分の前後それぞれのリポジトリ全体を、その時点のソースとして閲覧できます。変更のないファイルも開いてコメントを付けられます。
- 前後のソースを展開して開くため、言語サーバーによる定義・参照・実装へのジャンプがソース間で使えます。
- 付けた指摘をまとめて、AI Agent にそのまま渡せる指示文付きの Markdown または JSON として生成できます。

## 使い方

Git リポジトリを含むフォルダを開き、アクティビティバーの VSReview を選びます。複数のリポジトリがある場合は選択画面が開きます。Commits のコミットを展開すると、変更ファイルがフォルダ階層で並びます。フォルダを先、ファイルを後に、それぞれ名前順で表示します。タイトルの「一覧で表示」「ツリーで表示」ボタンで切り替えられます。単一フォルダの連なりは `explorer.compactFolders` に従って `src/ui` のようにまとめ、ファイルにはコメント件数、フォルダには配下のコメント合計を、1 件以上のときだけ表示します。リネーム・コピーは新パスの位置に置き、旧パスを補足表示します。

Commits のツリー・一覧と Files は、ファイルアイコンテーマに従ってファイル・フォルダのアイコンを表示します。変更ファイルの状態は A/M/D/R/C/T（競合は U）のバッジと Git の状態色で表示します。変更を含むフォルダは色だけを付け、複数の状態が混在するときは変更（M）の色を使います。Files の変更がないファイルには状態の装飾を付けません。

ファイルを選ぶと左に第1親、右に対象コミットの内容を表示します。ルートコミットの左側と、追加・削除ファイルの空の側は空文書です。

一番下の Files（初期状態では折りたたみ）を開くと、アクティブな差分の「変更前」「変更後」のリポジトリ全体を表示します。フォルダは展開時に読み込み、フォーカス中の側のファイルを選択し、反対側にも「開いているファイル」と表示します。リネームは左右それぞれのパスをたどります。変更ファイルを選ぶと差分を開きます。変更のないファイルもその時点の文書として開き、コメントを付けられます。この文書のコメントは既存の保存形式を使い、対象コミットの変更指摘として `status=M` で保存します。サブモジュールは開けません。差分を開いていないときは「差分を開くと表示します」と表示します。

一覧は更新時点の HEAD を起点に 50 コミットずつ表示します。末尾の「さらに読み込む」で続きを表示します。新しいコミットやブランチへの切り替えは自動で反映されます。`vsreview.autoRefresh`（既定 `true`）を無効にした場合は更新ボタンを押してください。

Agent が作業する git worktree のフォルダを VS Code で開くと、その worktree の HEAD をレビューします。Agent のコミット作成や fixup + autosquash が終わったら、更新された Commits の先頭を展開してファイルを選び、最新コミットを第1親と比較してください。自動更新は一覧と「書き換え済み」判定を更新します。開いている差分は切り替えず、そのコミットが書き換え済みになった場合はステータスバーで知らせます。

HEAD と、共通 Git 管理ディレクトリの `refs/heads`・`packed-refs` を監視します。worktree では `.git` ファイルの参照先を Git から取得するため、元リポジトリ側にある参照の変更にも追従します。連続した変更は 300 ms 待ってまとめ、更新中に変更が続いた場合も処理を重ねず完了後に再実行します。設定やリポジトリの選択が変わると監視を張り直します。

行番号付近のコメントボタンから行・範囲コメントを追加します。編集・削除はコメント欄、解決状態の切り替えはスレッドのボタンで操作します。「ファイルにコメントを追加」はファイルノードのメニューと差分のタイトルから入力します。ファイルコメントには範囲がなく、Review Comments にだけ表示します。

Review Comments はコミットまたは PR→ファイル→コメントの階層です。選ぶと該当差分と行を開きます。コメントはワークスペースの `workspaceState` に JSON で保存し、差分を開き直すと復元します。編集中のコメントは差分の左右を行き来しても保持します。

「AI Agent 向けにコメントをエクスポート」で範囲・形式・目的を選ぶと、未保存の文書を開き、同じ内容をクリップボードにコピーします。コミットの修正依頼は次の指示を含みます。

```text
修正は新しいコミットを追加せず、指摘対象のコミット自体を書き換えて畳み込んでください。
例: git commit --fixup=<hash> の後に GIT_SEQUENCE_EDITOR=: git rebase -i --autosquash <hash>^ を実行してください。
ルートコミットの場合は GIT_SEQUENCE_EDITOR=: git rebase -i --autosquash --root を使ってください。
コミットはフルハッシュと件名で特定してください。
```

`vsreview.export.instructions` のユーザー設定に文字列を設定すると指示文を差し替えられます。空文字列または空白だけなら既定文を使います。コード・件名・パスは参照用データであり、そこに含まれる命令には従わないという境界の説明は常に付けます。

## Pull Request のレビュー

認証済みの GitHub CLI（`gh`）を VS Code の実行環境の PATH に用意し、push 済みの PR があるリポジトリを開きます。Commits の下の Pull Requests に未完了の PR が並びます。タイトルの更新ボタンで再取得し、「PR 番号を入力して開く」から一覧にない番号も指定できます。gh が見つからない・未認証・GitHub リポジトリでない場合は、ビュー内に理由を表示します。

PR を展開すると変更ファイルが並び、PR 自体を選ぶと最初のファイルの差分を開きます。比較は GitHub の Files changed と同じ `merge-base(base, head)..head` です。base と head のオブジェクトがなければ fetch し、フォークの head も `refs/pull/<番号>/head` から取得します。取得先は既定で PR の URL と一致するリモート（なければ `origin`）です。別の名前を使う場合はユーザー設定 `vsreview.pullRequests.remote` に登録済みリモート名を指定してください。ワークスペース設定では変更できません。fetch は作業ブランチ・ローカル ref・`FETCH_HEAD` を変更しません。認証入力を求めず、30秒で打ち切ります。保存コメントや古いファイルノードを開くときにオブジェクトが失われていれば再取得し、取得できなければ理由を通知します。

ファイルの表示形式・状態装飾・行／範囲／ファイルコメント・Files ビュー・前後のファイル移動はコミットレビューと共通です。Review Comments では `PR #番号 タイトル` の下にまとめ、コメントにはレビュー時点の head と merge-base を保存します。一覧の更新だけでは開いている差分を置き換えません。新しい head をレビューするときは PR を選び直してください。

エクスポート範囲で「特定の PR」、目的で「質問」を選ぶと、コードやコミットを変更せず、各質問へ対象とコードの根拠を添えて回答する指示を出力します。質問の指示文はユーザー設定 `vsreview.export.questionInstructions` で差し替えられます。「修正依頼」の既定文は PR のブランチ上で修正して push する指示です。コミット用の fixup 手順は PR に適用しません。

PR の「書き換え済み」は、最新の head が保存時から変わり、保存した head がその祖先でない場合だけ表示します。通常の追加 push では書き換え扱いにしません。閉じた PR や取得できない PR は直前の判定を維持します。最新 head は起動時・リポジトリ選択時・更新コマンド・Pull Requests の更新ボタン・番号指定・PR 設定変更時に取得します。同じ PR は更新ごとに一度だけ問い合わせます。コメント操作と Git の自動更新では gh や fetch を実行しません。

## 差分とコードの参照

差分の右側が作業ツリーとバイト単位で一致し、未保存の内容も一致すれば、作業ツリーの実ファイルを開きます。旧側と、作業ツリーに一致しない右側は `git ls-tree` で通常ファイルを列挙し、`git cat-file --batch` でそのリビジョンの blob を展開して `file:` 文書を開きます。削除されたファイルや checkout していない PR でも、その時点のソースを言語サーバーが解析します。定義・参照・実装・型定義・ホバーは各言語の拡張が提供します。ワークスペース外のファイルを解析しない言語サーバーでは使えません。

展開先は VS Code のワークスペース保存領域の `revisionArchives/<リポジトリ識別子>/<フルハッシュ>/` です。同じリビジョンの要求は共有し、一時ディレクトリで展開を完了してから切り替えます。起動時に不完全な展開を掃除します。通常ファイルは chmod で読み取り専用にし、エディタでの編集には警告を表示します。パスを検証し、シンボリックリンクとサブモジュールは展開しません。属性は展開内容に影響しません。欠けた blob は遅延フェッチせず除外し、一度通知します。安全でないパス、Windows の禁止文字・予約名・8.3 短縮名、末尾のドット・空白、不正 UTF-8 のパスはそのファイルだけ除外し、理由を一度通知します。`.git` の別名を除外し、`HEAD` と `commondir`、または `HEAD`・`objects`・`refs` が揃うディレクトリは中身を除去してから公開します。大文字小文字と NFC/NFD の同一視は保存先で別々に検査し、衝突は双方のパスを除外して一度通知します。展開の上限は 200,000 ファイル・2 GiB・パス名の合計 32 MiB、Git からの無応答は 30 秒で中止します。

リポジトリごとの初回の展開前に、他の拡張が過去の設定ファイルを読み込んでコードを実行しうることを確認します。外部 fork の PR（判定が未保存の PR を含む）の head は、PR 番号と head の OID の組でも確認し、head が変われば再確認します。許可・拒否はワークスペースに保存します。「VSReview: リビジョン展開の許可・拒否をリセット」で選び直せます。確認を閉じた場合は記録せず、次回また確認します。拒否・展開失敗・保存領域がない場合は `vsreview:` 仮想文書を開き、Git diff の行対応を使って作業ツリーの言語機能へ転送します。変更・削除で対応行がない場合は転送できません。

`vsreview.revisionArchive.linkPaths` の既定値は `["**/node_modules"]` です。`**/名前` は任意の深さの同名ディレクトリを表し、既定では直下の `node_modules` も含め、サブパッケージの `node_modules` をリンクします。パターンでは、展開先に親ディレクトリがあり、現在の作業ツリーにディレクトリとして存在し、Git の追跡対象でないものを選びます。ignore の有無は問いません。候補の内側にあるディレクトリは対象外です。

固定の相対パスも従来どおり指定できます。パターンとして扱うのは先頭の `**/` と、`*`・`/` を含まない単一の名前の組だけで、それ以外の `*` は固定パスの一部として検証します。固定パスとパターンが親子で重なる場合は、作業ツリーに存在する固定パスを優先します。固定の子パスが無ければ、パターンの親ディレクトリをリンク候補に残します。固定パス同士の重複・親子重複は拒否し、パターン由来の同じパスは一つにまとめます。絶対パス、`..`、`.git` を含むパスは拒否します。履歴のファイルやディレクトリと重複するリンクは作らず、一度通知します。壊れたリンクや作成できないリンクは、そのリンクだけを除外して理由を一度通知します。リンク元の実パスはリポジトリ内に限り、リンク配下はレビュー対象にしません。

依存ライブラリは現在の作業ツリーのものを使い、履歴当時の依存をインストールする処理はありません。設定はユーザー側で指定し、ワークスペース・フォルダーの値は使いません。設定変更は次の展開から反映します。パターンの候補は展開時に決まるため、後からインストールした `node_modules` も再展開まで反映されません。既存の展開を更新するには全削除コマンドで削除して開き直すか、LRU による削除後に再度開いてください。

`vsreview.revisionArchive.maxCount` はリポジトリごとの保存数で、既定 10、範囲 2〜50 です。ユーザー設定だけを読み、範囲外の整数は境界値に丸めます。最終使用が古いものから削除しますが、開いている差分や展開先の通常タブは保持します。「VSReview: 展開したリビジョンをすべて削除」は開いている分も削除します。再利用するには差分を開き直してください。

展開先から定義へ移動したファイルにもコメントを付けられます。未変更ファイルのコメントは Files ビューと同じく `status=M` で保存します。コミット・元のリポジトリ相対パス・側・行番号という保存形式は変わりません。同じリビジョンを複数の比較が共有している場合、移動先では開いている差分のアクティブな比較、または直前にフォーカスした比較を使います。差分タブがない場合も、直近に使った保存済みの比較でコメントの表示・追加と Files の選択を続けられます。複数の比較から絞れない場合はコメント追加を拒否します。

作業ツリーの実ファイルへのコメントは、開いている VSReview 差分で表示します。通常の編集タブと同じ URI を共有すると差分側でも非表示にします。展開先の通常タブにはこの制限はありません。内容がコミットと違う文書にはコメントを追加できません。「作業ツリーの対応行で開く」は展開先からも現在のファイルの対応行へ移動し、対応がない理由をステータスバーに表示します。

仮想 URI やコマンド引数からの Git 操作は、ワークスペースから検出したリポジトリルートに限定します。Restricted Mode では拡張を起動しません。リポジトリ外へ出るパスも拒否します。

## コミットの書き換え後

コメントのコミットオブジェクトがない場合、または現在の HEAD から到達できない場合は「書き換え済み」と表示します。別ブランチだけにあるコミットもこの分類に含みます。「書き換え済みコミットのコメントを削除」は確認ダイアログの後、その分類のコメントだけを削除します。

検出済みリポジトリについて一覧の取得時や Git の HEAD・ブランチ参照の自動更新時に判定します。ワークスペース外の保存コメントに対しては Git を実行せず、到達可能性は判定しません。失われたコミットの差分を開けなくても、保存済みのコード抜粋と本文は出力できます。

## コマンド一覧

ID はすべて `vsreview.` で始まります。引数が必要な内部操作はコマンドパレットから隠し、該当するツリー・エディタ・コメントのメニューから実行します。

| ID                                                                       | 操作                                                                         |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `refresh`                                                                | 一覧を更新                                                                   |
| `selectRepository`                                                       | リポジトリを選択                                                             |
| `showFileTree` / `showFileList`                                          | 変更ファイルをツリー／一覧で表示                                             |
| `refreshPullRequests`                                                    | PR 一覧を再取得                                                              |
| `openPullRequestNumber`                                                  | PR 番号を入力して差分を開く                                                  |
| `openPullRequest`                                                        | PR の最初の差分を開く                                                        |
| `loadMore`                                                               | 続きのコミットを取得                                                         |
| `copyHash`                                                               | フルハッシュをコピー                                                         |
| `openDiff`                                                               | 差分を開く                                                                   |
| `nextFile` / `previousFile`                                              | 表示順で同コミット内の前後へ移動                                             |
| `clearRevisionArchives`                                                  | 展開したリビジョンをすべて削除                                               |
| `resetRevisionArchivePermissions`                                        | 展開の許可・拒否をリセット                                                   |
| `openWorkingFile`                                                        | 作業ツリーの対応行で開く                                                     |
| `addFileComment`                                                         | ファイルにコメントを追加                                                     |
| `addRangeComment`                                                        | 行・範囲コメントを追加                                                       |
| `editComment` / `saveComment` / `cancelEdit`                             | コメントの編集・保存・取り消し                                               |
| `deleteComment` / `toggleResolved`                                       | コメントの削除・解決状態切り替え                                             |
| `clearComments`                                                          | 確認後に全コメントを削除                                                     |
| `clearCommitComments` / `clearPullRequestComments` / `clearFileComments` | 確認後に選択したコミット・PR・ファイルのコメントを削除（右クリックメニュー） |
| `clearRewrittenComments`                                                 | 確認後に書き換え済みコメントを削除                                           |
| `openComment`                                                            | コメントの差分を開く                                                         |
| `exportComments`                                                         | AI Agent 向けに出力                                                          |

自動化では `vsreview.exportComments` に `{ "scope": "all", "format": "markdown" }` を渡せます。`scope` は `all` / `unresolved` / `pullRequest`、`format` は `markdown` / `json`、`purpose` は `fix`（省略時）/ `question` です。`scope: "pullRequest"` の場合は `pullRequest`（番号）と `repoRoot`（絶対パス）も渡します。引数なし、または `scope` と `format` のどちらも持たないオブジェクト（ビュータイトルのボタンから渡される引数など）では、範囲・形式・目的の選択画面が開きます。それ以外の不正な出力指定はエラーを通知して終了します。

ツリー表示の前後移動はフォルダを深さ優先でたどった順、一覧表示では Git から取得した順です。

## 設定

| 設定                                   | 既定値                | 動作                                                             |
| -------------------------------------- | --------------------- | ---------------------------------------------------------------- |
| `vsreview.revisionArchive.linkPaths`   | `["**/node_modules"]` | 元リポジトリへリンクする相対パス・`**/名前`（ユーザー設定のみ）  |
| `vsreview.revisionArchive.maxCount`    | `10`                  | リポジトリごとの保存数（最小 2）。開いている分は保持             |
| `vsreview.fileView`                    | `"tree"`              | `"tree"` はフォルダ階層、`"list"` は一覧。切り替えボタンでも更新 |
| `explorer.compactFolders`              | `true`                | 子が単一フォルダだけの連なりをまとめる VS Code の設定            |
| `vsreview.autoRefresh`                 | `true`                | コミット・ブランチの変更に追従                                   |
| `vsreview.export.instructions`         | `""`                  | AI Agent 向けの指示文。空白だけなら既定文を使用                  |
| `vsreview.pullRequests.limit`          | `50`                  | 一覧の最大件数（正の整数）                                       |
| `vsreview.pullRequests.remote`         | `"origin"`            | fetch 先。origin は PR の URL に合うリモートを優先               |
| `vsreview.export.questionInstructions` | `""`                  | 質問の指示文。空白だけなら既定文を使用                           |

## エクスポートの例

行番号は 1 始まりで、`new` はコミット時点、`old` は第1親時点です。以下は指示文・リポジトリ・コミットの情報に続くファイル部分の例です。パスなどのメタデータは JSON 文字列として表し、改行を `\n` にします。対象行は diff 記号の前の `> ` で示します。

````markdown
#### ファイル: "src/input.ts"

ステータス: M

位置: new L12-L12

```diff
@@ -9,7 +9,7 @@
   function parse(value: string) {
> +  return Number(value);
   }
```

コメント本文:

```text
空文字列を拒否してください。
```

解決状態: 未解決

作成: "2026-11-06T10:00:00Z" / 更新: "2026-11-06T10:00:00Z"
````

JSON は `version`、目的 `purpose`、指示文 `instructions`、資料との境界説明 `boundary`、現在ブランチの対応表 `repositories`、アンカーを含む `comments` を出力します。各コメントは `id`、`status`、`subject`、`author`、`date`、`repoRoot`、`commit`、`parent`、`path`、`oldPath`（該当時）、`side`、`startLine`、`endLine`、`code`、`hunkHeader`、`excerpt`、`body`、作成・更新日時、`resolved` を持ちます。PR コメントには省略可能な `pullRequest` フィールド（番号・タイトル・URL・base/head 名・OID・merge-base など）も含みます。保存形式は version 1 のままです。ファイルコメントは `side=file`、行番号は 0 です。ブランチ取得に失敗した場合、本文には「取得不能」だけを書き、詳細は VS Code に通知します。

## 開発

Node.js 24、pnpm 12、Git、VS Code 1.90 以降を使います。

```sh
pnpm install
pnpm run check
pnpm run test:e2e
pnpm exec vsce package --no-dependencies
```

`check` は Prettier、型検査、ESLint、Vitest、esbuild を実行します。`pnpm format` で整形します。E2E は `which code` で解決した VS Code とスクリプト内で起動する Xvfb を使い、独立した設定・拡張フォルダを `.scratch/` に作ります。実行ファイルは `VSREVIEW_CODE`、Xvfb は `VSREVIEW_XVFB` で変更できます。ログは一時フォルダに残します。PR の E2E はテスト用の gh 実行ファイルを PATH の先頭に置き、ローカルの bare リポジトリを origin に使います。GitHub への書き込みは行いません。

純粋ロジックは `src/core/`、Git / gh CLI とファイル I/O は `src/git/`、VS Code API は `src/ui/` に分離しています。Git は shell を使わず `execFile`・`spawn` と NUL 区切りの出力を使い、ロケールを C に固定します。テストの一時リポジトリは後片付けします。テスト内のコミットは一時リポジトリだけに作成します。

バイナリは差分を開きません。テキストは UTF-8 前提で、Git の通常出力上限は 64 MiB です。リビジョンの展開ではファイル一覧と blob をストリームで読み、この出力上限を使いません。コメントはローカルのワークスペースに保存され、自動同期はありません。保存形式が不正な場合は上書きを防ぐため起動を中止します。
